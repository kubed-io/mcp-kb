# kubed-mcp 0.8 Implementation Plan

> **History.** Proposed for #126 (PR #127, into `main`). The spec is
> [2026-11-28-kubed-mcp-0.8-design.md](2026-11-28-kubed-mcp-0.8-design.md). It finishes #126's
> approved notes and replaces them as the design of record. It was checked against `main` and
> quick-mcp's `v0.8.0` source. Its decisions are D1 to D10. The requirement text it gives is what
> the tasks write into `specs/`. On PR #127 at 07:55, Dr K accepted the plan's calls. He also ruled
> that Task 3 stops at Step 4: he generates `.pyroscope.yaml` himself, from an image of this branch
> (D10).

> **For agentic workers:** REQUIRED SUB-SKILL: Use skill://superpowers/subagent-driven-development/SKILL.md (recommended) or skill://superpowers/executing-plans/SKILL.md to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** kb runs kubed-mcp 0.8:
- it serves one listing per Via;
- a cold pod keeps answering while it builds;
- under the default Via, every single-library client is told its skill names;
- the image carries its own source, so Pyroscope links each frame to the commit it was built from.

**Architecture:** almost all of it is upstream's.
- kb moves its pin.
- It moves the tests that send `skills/list` onto Via `extension`, by one helper per transport.
- It drops one parameter from `build_instructions` (INS-11).
- It adds two metadata lines to the end of the Dockerfile and one build arg to the bake file.
- It commits the `.pyroscope.yaml` the image writes.

**Tech Stack:** Python ≥3.11, kubed-mcp 0.8 (FastMCP through its facade), pytest +
pytest-asyncio, uvicorn (`tests.conftest.serve_http`), Docker buildx bake over
`docker-compose.yaml`.

**Spec:** [2026-11-28-kubed-mcp-0.8-design.md](2026-11-28-kubed-mcp-0.8-design.md). It changes
these living spec rows:
- [scoping-and-instructions.md](../specs/scoping-and-instructions.md): INS-2, INS-11 and INS-19,
  and removes INS-3;
- [skills.md](../specs/skills.md): SKL-62;
- [prompts.md](../specs/prompts.md): PRM-64;

## Global Constraints

- The pin is exactly `"kubed-mcp>=0.8.0,<0.9",` in `pyproject.toml`'s `dependencies`. The
  `telemetry` and `test` extras keep `kubed-mcp[telemetry]` unpinned.
- kb sets no `delivery.via`, `delivery.max` or `delivery_default`. The default Via stays `mcp`.
  Only tests set `delivery.via`, through `extension_kb`.
- `catalogue/` and `plugins/` import no FastMCP and no `kubed.mcp` type
  (`tests/test_boundaries.py`).
- In tests, `extension` is reached one way per transport, and only these two (D2):
  `tests.conftest.extension_kb` in memory, and `tests.conftest.VIA_EXTENSION` over HTTP.
- Spec IDs are stable and never reused. INS-3 is removed and leaves a gap. HTTP-49 is the one new
  ID. Spec files hold statements only: no dates, no issue numbers, no "used to".
- `.pyroscope.yaml` is only ever the output of `--write kubed-mcp-kb` run in the image, and Dr K
  commits it (D10). No agent writes or edits it.
- Generated wiki pages come only from `python scripts/generate_wiki.py`. Wiki edits go on the
  wiki submodule's `issue-126` branch, never `master`. Commits are signed (`git commit -S`).
- `CHANGELOG.md`: edit `[Unreleased]` only. No BREAKING line (Dr K's ruling).
- Markers: in-process tests are `@pytest.mark.unit`, uvicorn ones `@pytest.mark.integration`, and
  `tests/live/` is `live`.
- Every task passes, from the repository root with `wiki/` checked out:
  `ruff check . && pytest && python scripts/generate_wiki.py --check`. That is `test.yml`'s lint
  and suite (3.11 and 3.14 in CI) plus the wiki drift check. Task 3 also passes hadolint
  (`lint.yml`'s Dockerfile Lint).
- Do not weaken an assertion to make it pass. A failure the design does not explain is a finding:
  stop and report it with the output.

## Review Focus

1. **A client that declares the Skills extension but sends no Via.** It gets an empty
   `skills/list` and its skills as `resources/list` rows, so the instructions must still name them
   (INS-11). Task 2 (`test_a_declared_extension_without_via_reads_from_resources`).
2. **A local build with no `GIT_SHA`.** The ref must be empty, which is no label, and never
   `latest`, which links every frame to a 404. Task 3
   (`test_the_bake_passes_the_commit_and_no_stand_in`).
3. **A `RUN` added to the runner stage later.** Below `ARG GIT_SHA`, it would rerun on every
   commit. Task 3 (`test_the_image_names_its_source_after_every_run`).
4. **The cap under `extension`.** `Kb-Max` cuts `skills/list` exactly as it cuts the default's
   resource rows, and the cut line is the same. Task 1 (`MAX_INPUTS`, both halves of
   `test_the_max_cuts_both_listings_alike`).
5. **A gateway prefix under `extension`.** Entries keep plain structured URIs, and the digests
   match the prefixed reads. Task 1 (`test_skills_extension_with_the_prefix`, moved onto
   `VIA_EXTENSION`).

def test_the_image_names_its_source_after_every_run():
    """HTTP-49: the labels change with every commit, so nothing below them may rebuild."""
    runner = dockerfile_stages()["runner"]
    at = runner.index("ARG GIT_SHA")
    assert not [ln for ln in runner[at:] if ln.startswith("RUN ")]

## For Dr K: the CI step (the App cannot edit `.github/`)

In `.github/workflows/image.yml`, add `- .pyroscope.yaml` to `on.push.paths`, so a commit that
only regenerates the file is checked. Then add this step after "Build and Push":

```yaml
    # The committed .pyroscope.yaml should be what this image implies. A kubed-mcp
    # or Python patch makes it stale with no commit of ours, so this warns and never
    # fails. build-image's bake is two-arch with no --load: the image exists only
    # once pushed, so a dry run skips this and the image is pulled by its short sha.
    - name: Check .pyroscope.yaml
      if: env.PUSH == 'true'
      shell: bash
      run: |
        sha=$(git rev-parse --short HEAD)
        set +e
        diff=$(docker run -i --rm --entrypoint python "kubed/mcp-kb:${sha}" \
          -m kubed.mcp.pyroscope --check kubed-mcp-kb < .pyroscope.yaml)
        status=$?
        set -e
        if [ "$status" -ne 0 ]; then
          echo "::warning title=.pyroscope.yaml::does not match kubed/mcp-kb:${sha} (exit ${status}); regenerate it with --write kubed-mcp-kb in the image"
          {
            echo "### .pyroscope.yaml does not match kubed/mcp-kb:${sha}"
            echo
            echo '```diff'
            echo "$diff"
            echo '```'
          } >> "$GITHUB_STEP_SUMMARY"
        fi
```

Exit 1 carries the diff. Exit 2 (an unreadable file or an unmappable image) and a failed pull warn
with an empty diff.
