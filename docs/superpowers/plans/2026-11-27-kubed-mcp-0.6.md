> **History.** Proposed for #111 (PR #121, into `issue-112`, after #115, #116 and #119 merged
> there). The spec is [2026-11-27-kubed-mcp-0.6-design.md](2026-11-27-kubed-mcp-0.6-design.md).
> It finishes #111's approved notes and replaces them as the design of record, checked against
> `issue-112`'s head and quick-mcp's `v0.6.0-rc.4` source. Its decisions are D1 to D11. The
> requirement text it gives is what the tasks write into `specs/`. Dr K's rulings on PR #121 at
> 13:42 changed two things: the floor is rc4 (D1), and the live check derives the cut skills from
> the route rather than naming them (D10).

> **For agentic workers:** REQUIRED SUB-SKILL: Use skill://superpowers/subagent-driven-development/SKILL.md (recommended) or skill://superpowers/executing-plans/SKILL.md to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** kb runs kubed-mcp 0.6. It conforms to SEP-2640 final. It lists at most 100 skills
unless told otherwise, and says so in its instructions when it cut some. It shuts down cleanly.

**Architecture:** almost all of it is upstream's.
- kb moves its pin and regenerates what is generated from the schema.
- It changes one constant, the `extension` footer (INS-21).
- It adds one optional paragraph to `build_instructions`, fed from `Resolved.skills` by
  `ScopedInstructions` (INS-24).
- The rest is tests that pin upstream's behaviour as kb serves it, and the spec, the wiki and the
  changelog.

**Tech Stack:** Python ≥3.11, kubed-mcp 0.6 rc (FastMCP through its facade), pytest +
pytest-asyncio, uvicorn (`tests.conftest.serve_http`).

**Spec:** [2026-11-27-kubed-mcp-0.6-design.md](2026-11-27-kubed-mcp-0.6-design.md). It changes
these living spec rows:
- [scoping-and-instructions.md](../specs/scoping-and-instructions.md): SCP-2, SCP-3, INS-14,
  INS-20 and INS-21, and the new INS-24.
- [skills.md](../specs/skills.md): SKL-14, SKL-24, SKL-30, SKL-33, SKL-46, SKL-48, SKL-51,
  SKL-56, SKL-57 and SKL-62, and the new SKL-63 and SKL-64.

## Global Constraints

- The pin is exactly `"kubed-mcp>=0.6.0rc4,<0.7",` in `pyproject.toml`'s `dependencies` (D1).
  The `telemetry` and `test` extras keep `kubed-mcp[telemetry]` unpinned.
- kb sets no `delivery.max` and defines no `delivery_default` (D7). It wraps no upstream answer
  (D6).
- `catalogue/` and `plugins/` import no FastMCP and no `kubed.mcp` type
  (`tests/test_boundaries.py`). `build_instructions` takes plain ints.
- `LabelKbReads` stays at `mcp.server.middleware.insert(1, …)`. `tests/test_read_labels.py`'s miss
  tests pass unchanged.
- The `extension` footer is exactly `Skills arrive through the Skills extension; each reads at skill://<library>/<path>/SKILL.md, and its entry lists the files it ships.`
- The cut line is exactly `{listed} of {total} skills are listed; every skill reads through its library's _index.md.`
- Spec IDs are stable and never reused. The new ones are SKL-63, SKL-64, INS-24 and HTTP-48.
  Spec files hold statements only: no dates, no issue numbers, no "used to".
- Generated files come only from their generators:
  - `config.schema.json` from `python -m kubed.mcp_kb schema > config.schema.json`;
  - `wiki/Configuration.md`, `Tools.md` and `Endpoints.md` from `python scripts/generate_wiki.py`.
- Wiki edits go on the wiki submodule's `issue-111` branch, never `master`. Commits are signed
  (`git commit -S`).
- Markers: in-process tests are `@pytest.mark.unit`, and uvicorn ones `@pytest.mark.integration`.
- Every task passes, from the repository root with `wiki/` checked out:
  `ruff check . && pytest && python scripts/generate_wiki.py --check`. That is `test.yml`'s lint
  and suite (3.11 and 3.14 in CI) plus the wiki drift check.
- Do not weaken an assertion to make it pass. A failure the design does not explain is a finding:
  stop and report it with the output.

## Review Focus

1. **A max of exactly the skill count** (`Kb-Max: 4` on the 4-skill tree). It lists every skill,
   cuts none, and writes no cut line. Task 3 (`MAX_INPUTS`) and Task 4
   (`test_a_max_that_cuts_nothing_writes_no_line`).
2. **An invalid max under a valid one.** `Kb-Max: 0` with `?max=3` lists 3, because an invalid
   value falls through to the next source, unlike SCP-5's first-source-wins. Task 3
   (`MAX_INPUTS`).
3. **A cap under a scope.** It cuts from what the scope admits: `Kb-Library: flatsource` with
   `Kb-Max: 1` lists `alpha`, and the line reads `1 of 2`. Task 3 and Task 4.
4. **A tools-mode client** (`Kb-Resources: off`). The `list_resources` tool is capped exactly as
   `resources/list` is, and keeps `_files.md`. Task 3
   (`test_the_tool_mirror_is_capped_alike`).
5. **A prefix with a cut.** The cut set is the same, and the line is the same text as without the
   prefix: `_index.md` in it is not an address. Task 4
   (`test_the_cut_line_is_told_on_connect`, the prefixed case).
