# kubed-mcp 0.3 Pin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use skill://superpowers/subagent-driven-development/SKILL.md (recommended) or skill://superpowers/executing-plans/SKILL.md to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** kb runs on `kubed-mcp>=0.3.0,<0.4`. Nothing it serves changes except what kubed-mcp
0.2.0 and 0.3.0 name: the `_meta["io.kubed/delivery"]` echo on the handshake, VS Code listing the
resource pair with no header, and the titles TOOL-6 already gives that pair.

**Architecture:** One dependency line in `pyproject.toml`, then the whole suite on the new release.
On `issue-80` kb serves through kubed-mcp's plugin layer: `SkillServing.publish` adds every plugin
to a plugin set, `list_resources` and `read_resource` are the layer's (DLV-6), and `create_app`
passes `header_prefix="Kb"`. So kubed-mcp's delivery resolution is kb's own for resources and the
prefix. 0.2.0's known-clients table and handshake echo reach kb unchanged. Task 2 pins both.

**Tech Stack:** Python ≥3.11, `kubed-mcp` 0.3.0 (FastMCP through its facade), pytest +
pytest-asyncio, uvicorn for the HTTP tests.

**Spec:** this file's Design section (the change is too small for a design doc of its own),
[TOOL-2](../specs/http-and-tools.md), reworded in Task 1, and
[HTTP-42](../specs/http-and-tools.md), added *(proposed)* with this plan and settled in Task 2.
Starts from #92's notes, adopts a release of kubed-io/quick-mcp#16, and carries Dr K's retarget
from 0.2.0 to 0.3.0 and from `main` to `issue-80`.

## Design

**The pin.** The branch is based on `issue-80`, where the line is `"kubed-mcp==0.2.0rc2"`
(`pyproject.toml:33`). It becomes `"kubed-mcp>=0.3.0,<0.4"`: an exact `==` is the form for release
candidates only. kb pins once, past rc3 and 0.2.0, so #78 (telemetry) builds on this pin with no pin
change of its own. It is the only kubed-mcp pin: `scripts/requirements.py` reads pyproject, and CI
installs `.`, `.[test]` and `.[test,build]`. Nothing installs from git.

**What reaches kb from rc2 to 0.3.0.** The merged tree was run on rc2 (1330 passed) and on 0.3.0
(1329 passed, one failure), with nothing else installed differently. Nothing is refused: the plugin
set and kubed-mcp's resource pair start on 0.3.0 as on rc2. 0.3.0 is 0.2.0 plus telemetry, which is
the `[telemetry]` extra, loads lazily, and kb does not take it.

| kubed-mcp, rc2 to 0.3.0 | What kb serves |
|---|---|
| The resource pair's annotations carry a title: "List resources", "Read a resource" | `tools/list` gains the two titles TOOL-6 already names. The generated `Tools.md` gains two rows. That is the one failing test, `test_the_generated_pages_are_current`. Task 1 regenerates the page, with no spec change |
| Known clients: a `clientInfo.name` starting "Visual Studio Code" resolves `resources: off` when no header or parameter says otherwise (DLV-15) | VS Code with no header now lists `list_resources` and `read_resource`, in both eras. rc3 named this change for kb. TOOL-2 says a request that declares neither sees no tools, so Task 1 rewords it. #86 no longer has to make this change. No existing test covers it; Task 2 adds one |
| `initialize` and `server/discover` carry `_meta["io.kubed/delivery"]`: `{"resources", "listed", "via", "prefix"}` | Every handshake carries it. rc2 sent none. With `header_prefix="Kb"`, kubed-mcp reads the `Kb-` names too (`delivery.py:459-460`), so the echo agrees with what kb serves: a `Kb-Resource-Prefix` is echoed, and VS Code's `resources: off` matches the pair it is listed. Task 2 proves it by running it, and settles HTTP-42 |
| `X-MCP-Via`, `X-MCP-Listed`, `delivery_default`, `mcp.instructions` | Not used here. They come with #87 |

**What HTTP-42 said, and why it changes.** Written against `main`, HTTP-42 said the echo can
disagree with kb, because kb passed no `header_prefix` and owned its mirror tools. On `issue-80`
neither holds. Task 2 rewrites it to say the echo reports what the request resolved and kb serves,
once its tests show that. If a test disagrees with `delivery.py`, the task stops and reports.

**Not in this change:** the `[telemetry]` extra, `X-MCP-Via`, `X-MCP-Listed`, `delivery_default`
and `mcp.instructions` (#87), and any change to `kubed/` beyond what a test proves is needed. Dr K
accepts the echo as kubed-mcp writes it until #86/#87.

## Global Constraints

- **Pin, verbatim:** `"kubed-mcp>=0.3.0,<0.4",`. Keep the comment above it. Its sentence
  "Pre-1.0, so a minor is a break." stays.
- **Toolchain, as CI runs it:** `pip install -e ".[test]"`, then `ruff check .` and `pytest` from
  the repository root (`test.yml`). The `wiki/` submodule must be checked out so
  `tests/test_wiki.py` runs and does not skip. Package (`package.yml`): `python -m build` and
  `twine check --strict dist/*`. Dependency audit (`lint.yml`): `pip install -e .`,
  `pip freeze --exclude-editable > requirements.txt`, `pip-audit -r requirements.txt`, the
  requirements file written outside the repository.
- **Python 3.11 is the floor.** Lines are at most 88 columns. A pull request is tested on 3.11 and
  3.14.
- **Through the facade only** in `kubed/`: never import `fastmcp`, `mcp` or `mcp_types` there.
  Tests already import `fastmcp.Client` and may import `mcp.types.Implementation`.
- **Do not weaken an existing assertion to make it pass on 0.3.** A test that fails for a reason
  this Design does not name is a finding: stop and report it with the output.
- **Markers:** an in-process test is `@pytest.mark.unit`, and a uvicorn one is
  `@pytest.mark.integration`.
- **The wiki is a submodule.** Edit its files in place and run no git inside it. Generated pages
  come from `python scripts/generate_wiki.py`; never edit `Tools.md` by hand.
- **Public repo:** the maintainer is Dr K; no names or real hostnames.
- **Commits** link kubed-io/quick-mcp#16 and end with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **VS Code with no header lists the resource pair, and only it.** A plain client lists no
   tool. → Task 2, `test_vs_code_lists_the_resource_pair_without_a_header`.
2. **The echo agrees with what is served**, in both eras: `resources` matches the tools listed, and
   `prefix` is the prefix every served URI carries. That holds for `Kb-Resource-Prefix`,
   `X-MCP-Resource-Prefix` and `?prefix=`. → Task 2, `test_the_handshake_echo_matches_what_is_listed`
   and `test_the_echo_names_the_prefix_every_address_carries`.
3. **No `kb+kb+`, and digests match the bytes read**, under each prefix input. → Task 2, the
   prefix test.
4. **`Tools.md` changes by the two title rows alone.** → Task 1, Step 4.
5. **TOOL-2 and the changelog say what VS Code now sees.** → Task 1, Steps 3 and 5.

### Task 2: Pin what 0.3 does to kb's handshake and listing

**Files:**
- Test: `tests/test_server.py` (`KnowledgeBase`, `make_config`, `server_of`, `call`, `request`
  from `tests.test_skills_extension`)

  `tool`, `skills_request`, `PIN`, `INPUTS`)

- Modify: `wiki/Installing.md`, if Step 2 proves the opt-out

**Interfaces:**
- Consumes: Task 1's environment.
- Produces: `DELIVERY_META = "io.kubed/delivery"` and
  `VS_CODE = Implementation(name="Visual Studio Code", version="1.99.0")` (from `mcp.types`),
  module constants in `tests/test_server.py`.

- [ ] **Step 1: Write the tests**

  In `tests/test_server.py`, both `@pytest.mark.unit`, in-process, parametrized over
  `mode` in `("legacy", "auto")`:
  - `test_vs_code_lists_the_resource_pair_without_a_header(skills_dir, mode)`:
    `Client(server_of(server), mode=mode, client_info=VS_CODE)` with no header lists exactly
    `["list_resources", "read_resource"]` (sorted names), and
    `await call(client, "read_resource", uri="skill://flatsource/_index.md")` contains
    `skill://flatsource/alpha/SKILL.md`. The same server with no `client_info` lists `[]`.
  - `test_the_handshake_echo_matches_what_is_listed(skills_dir, mode)`: the echo is
    `client.initialize_result.meta[DELIVERY_META]` in `legacy` and
    `(await request(client, "server/discover"))["_meta"][DELIVERY_META]` in `auto`. For a plain
    client it reads `resources: "on"` and `prefix: None`, and the client lists no tool. For
    `VS_CODE` it reads `resources: "off"`, and the client lists the resource pair.

  In `tests/test_addressing_http.py`, `@pytest.mark.integration`, parametrized over `INPUTS`
  (`kb-header`, `x-mcp-header`, `parameter`), the URL `server_url + query` with
  `{**PIN, **headers}`:
  - `test_the_echo_names_the_prefix_every_address_carries(server_url, sent)`:
    - The echo's `prefix` is `"kb+"`. Read it from the HTTP client's handshake, from
      `initialize_result.meta` or from `server/discover`'s `_meta`, whichever the default mode
      gives.
    - With no prefix input, the same echo's `prefix` is `None`.
    - Every URI the server hands back carries the prefix once:
      - `read_resource("kb+skill://flatsource/alpha/SKILL.md")` returns contents whose `uri` is
        `kb+skill://flatsource/alpha/SKILL.md`
      - `list_resources`, with `Kb-Resources: off` added, returns rows whose `uri` all start
        `kb+skill://`
      - the index body cites `kb+skill://flatsource/alpha/SKILL.md`
      - no `kb+kb+` appears anywhere
    - Every file `skills/get` lists for `skill://flatsource/alpha/SKILL.md` has a `digest` equal
      to `sha256:` plus the hash of the bytes a read of its `uri` returns.
  - `test_vs_code_can_turn_the_resource_pair_off(server_url)`: an HTTP client with
    `client_info=VS_CODE` (imported from `tests.test_server`) and `Kb-Resources: on` lists no
    tool. kubed-mcp walks the header before its known-clients table (DLV-15).

- [ ] **Step 2: Run them**

  - **`Kb-Resources: on` does not hide the pair for VS Code:** drop that test, and say so in the
    report and the commit body. Leave the wiki unchanged.
